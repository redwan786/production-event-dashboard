# Supabase setup guide — NEW project only

1. Sign in at supabase.com and create a **new project** with a new project name. Choose an organization and region. Set a strong database password and store it privately. Wait until the project is ready. Do not select your traffic-project database.
2. On the new project's dashboard, use **Connect** and choose a PostgreSQL connection string. For an IPv4-compatible connection choose **Session pooler**, usually port 5432. Direct connections may require IPv6. Supabase's transaction pooler has different connection semantics; use session mode for this guide. Confirm the hostname and project reference belong to the new project. Do not post the connection string in chat.
3. In PowerShell, inside the project folder, run `Copy-Item .env.example .env` and `notepad .env`. Replace the placeholder DATABASE_URL with your new project's session-pooler connection string. Substitute the database password privately; URL-encode special password characters if needed. Remove `?sslmode=...` and other ssl parameters from the URL: the app explicitly verifies TLS. Save the file. The .gitignore excludes .env.
4. Node verifies the server certificate with its trusted CAs. If Supabase provides a project CA certificate and the default trust store cannot verify the connection, download the CA from the new project's database settings and set `PG_CA_CERT_PATH` in .env to the local file path. Keep the certificate file outside the repository; never disable verification. Check the current Supabase dashboard for exact labels.
5. Confirm the URL points to the NEW project before running `npm run migrate`. The initial migration uses CREATE TABLE/INDEX IF NOT EXISTS and contains no DROP or DELETE; it still creates tables, so do not run it against an unrelated database. Stop if unsure. It does not reset existing tables.
6. Run `npm start` and visit http://localhost:3000/health. A connected response confirms a database query succeeded, not which project you selected. Verify the project reference separately in Supabase. If a connection fails, check host, port, password encoding, TLS CA and network support without sharing secrets.

A deployed Render service can use this same NEW session-pooler connection string via private environment settings; detailed deployment instructions will be added when deployment support is complete.

## Using the same new database on Render
See RENDER_DEPLOYMENT_GUIDE.md. Enter `DATABASE_URL` and any CA privately in Render's environment settings or secret file; the app enforces certificate verification. Do not assume a Supabase project CA is appropriate for the pooler's separate public certificate chain. Neither the new connection nor Render deployment is verified until you test them.
